# Instructions for AI Agents

This application repository uses [ALM4Dataverse](https://github.com/ALM4Dataverse/ALM4Dataverse)
to export, build, and deploy Microsoft Dataverse solutions. Application-specific
configuration, unpacked solutions, source projects, and hooks belong in this repository;
the shared automation and detailed guides live in the ALM4Dataverse repository.

## Read The Docs For The Version In Use

The links below point at `main`. This repository may use a different version of the
shared code, and its behavior and settings can differ. Find the version in use:

- **GitHub Actions:** the ref after `@` in `uses: ALM4Dataverse/ALM4Dataverse/...@<ref>`
  in `.github/workflows/*.yml`.
- **Azure DevOps:** the `ref` of the `ALM4Dataverse` repository resource in
  `pipelines/*.yml`. Without a `ref`, it is the default branch of the shared repository
  in the same Azure DevOps project; read the `docs` folder there.

To read a page for a ref, replace `blob/main` with `blob/<ref>` in its link.

## Before Changing Anything

1. Read the task guide for [adding solutions, plug-ins, web resources, and Code Apps](https://github.com/ALM4Dataverse/ALM4Dataverse/blob/main/docs/usage/adding-dataverse-components.md).
2. Check the [ALM configuration reference](https://github.com/ALM4Dataverse/ALM4Dataverse/blob/main/docs/config/alm-config.md) and the relevant [export](https://github.com/ALM4Dataverse/ALM4Dataverse/blob/main/docs/usage/exporting-changes.md), [build](https://github.com/ALM4Dataverse/ALM4Dataverse/blob/main/docs/usage/building-releases.md), or [deployment](https://github.com/ALM4Dataverse/ALM4Dataverse/blob/main/docs/usage/deploying.md) guide.
3. Use and extend the solution list and mappings in `alm-config.psd1`. Dataverse components must be part of a solution; the `assets` setting only copies extra files into the build artifact.

## Who Owns Which Files

- `solutions/<unique-name>/` is written by EXPORT, which deletes and re-creates it from
  the development environment. Don't edit it by hand: make the change in Dataverse
  and export, or keep the source in this repository and map it into the solution with
  `mappings` or `codeApps`, as the components guide describes.
- `alm-config.psd1`, `data/`, hook scripts and source projects belong to this
  application. Edit them freely.
- Caller workflows and pipelines are generated by setup. Keep edits small, because a
  setup re-run can replace them; see
  [re-running setup](https://github.com/ALM4Dataverse/ALM4Dataverse/blob/main/docs/usage/updating.md#re-run-setup-carefully).

The [repository layout](https://github.com/ALM4Dataverse/ALM4Dataverse/blob/main/docs/concepts/application-repository.md)
page describes each file.

## Writing Hooks

Follow [writing hooks](https://github.com/ALM4Dataverse/ALM4Dataverse/blob/main/docs/usage/writing-hooks.md).
In short: a hook is a script with `param([hashtable]$Context)`, listed under `hooks` in
`alm-config.psd1`. Deployment hooks run from the build artifact, so their files must be
listed in `assets`. They also run during IMPORT and BUILD validation, and again on every
retry, so make them safe to repeat. Throw on failure.

## Checks Before Committing

- `Import-PowerShellDataFile ./alm-config.psd1` must succeed.
- Changed `.ps1` files must parse without errors.
- Run the owning project's build for any changed source project.

BUILD runs the full packaging checks when the change is pushed; review its result.

## Rules

- Never add credentials, tokens, connection strings or environment-specific secrets to
  source control. They belong in the CI platform's secrets or variable groups.
- Prefer the shared documentation and this repository's existing configuration over
  assumptions.
